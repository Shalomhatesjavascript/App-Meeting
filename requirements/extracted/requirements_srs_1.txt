 
 Software Requirements Specification (SRS) 1. Introduction 1.1 Purpose This document describes the requirements for a Babcock University–exclusive meetup application. 1.2 Scope The system is a web-based application accessible only to verified Babcock University students. 1.3 Definitions Match: Mutual interest between two users Intent: Purpose of using the app 1.4 References IEEE 830 SRS Standard 1.5 Overview This document outlines functional and non-functional requirements. 2. Overall Description 2.1 Product Perspective The system is a standalone web application. 2.2 Product Functions - User registration and verification - Matching system - Messaging - Subscription management - Admin moderation 2.3 User Classes - Students (Free) - Students (Paid) - Admin 2.4 Operating Environment Web browsers and containerized mobile app. 2.5 Constraints Email restriction, weekly match limits. 2.6 Assumptions Users are active students. 3. System Features 3.1 Authentication Email verification via @student.babcock.edu.ng 3.2 Profile Management Users can create and edit profiles. 3.3 Matching System Swipe-based matching with weekly limits. 3.4 Messaging Text-based chat after match. 3.5 Monetization Weekly subscriptions for premium features. 3.6 Admin Dashboard User management and reports. 4. External Interface Requirements 4.1 User Interfaces Responsive web UI. 4.2 Hardware Interfaces None. 4.3 Software Interfaces Payment gateways and email services. 4.4 Communication Interfaces HTTPS. 5. Non-Functional Requirements 5.1 Performance System should handle concurrent users. 5.2 Security Authentication, authorization, data encryption. 5.3 Usability Simple swipe-based UI. 5.4 Scalability Support increased users. 5.5 Maintainability Modular architecture. 6. Other Requirements Audit logs, analytics, moderation tools. 7. Appendices Future enhancements and glossary.
